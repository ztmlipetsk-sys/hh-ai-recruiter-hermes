# Согласование ответов кандидатам

Реализация от 28 сентября 2026 года. Вопросы и другие входящие сообщения кандидатов выбранной вакансии поступают владельцу в отдельный личный Telegram-бот. В карточке есть кандидат, вакансия, ID чата и сообщения, дата, полный текст и черновик. Кнопки: «Утвердить и отправить», «Изменить ответ», «Отклонить». Кандидат получает ответ в исходном чате HH только после нажатия владельцем кнопки под конкретной версией ответа.

## Что готово

- SQLite-очередь с дедупликацией по чату и сообщению, версиями текста и журналом решения.
- Новый официальный HH API `/common/chats`; старые методы `/negotiations/.../messages` не используются.
- Чтение всех доступных страниц чатов выбранной вакансии и сообщений с проверкой продвижения курсора.
- Передача всех входящих текстов кандидата для рассмотрения: классификатор вопросов не используется, чтобы не потерять вопрос без вопросительного знака.
- Длинные тексты разделяются без обрезки; вложения требуют просмотра в HH и блокируют автоматическую отправку.
- Проверка числового ID владельца и личного чата; обычное «да» не подтверждает отправку.
- Кнопка привязана к случайному токену карточки и её версии. Старые кнопки после правок/отказа/отправки недействительны.
- Перед POST проверяются текущая вакансия, права записи и неизменность вопроса. Новые сообщения после вопроса блокируют устаревший ответ.
- POST содержит UUID идемпотентности. Нет автоматических повторов отправки. Timeout, авария после начала отправки и неподтверждённый ответ сохраняются как `unknown`; история HH проверяется вручную.
- Действующий `hh_api.py`, шкала и база оценок не изменены.

## Границы

Это отдельный обработчик стандартной библиотеки Python 3.10+, а не обновление установленного Hermes. Он не использует LLM и не выдумывает условия вакансии. Предлагает нейтральное «Спасибо за вопрос. Я уточню информацию и вернусь к вам с ответом». Владелец заменяет его кнопкой «Изменить ответ». Hermes может подготовить предметный черновик в UTF-8 файле и вызвать режим `draft`; это не разрешает отправку.

Нужен ОТДЕЛЬНЫЙ Telegram-токен, не используемый gateway Hermes или другим polling-процессом. Работающий шлюз нельзя останавливать/перенастраивать ради этого обработчика. Автоматически выпускать токен за пользователя, обходить вход или копировать секреты ChatGPT программа не умеет.

Ссылка в карточке ведёт в `https://hh.ru/chat`; для поиска указаны точные ID чата и сообщения. Это не обещание прямой ссылки на конкретную переписку. API не предоставил документированный deep link.

Реальный Windows-ПК, Telegram и HH в этой сессии недоступны. Сквозной сетевой тест не проведён, сообщения реальным людям не отправлялись. Отсутствие ответа API не считается успешной отправкой.

## Запуск

Сохраните существующую установку и её конфигурацию. Скачайте ветку с этой доработкой в отдельную папку, не поверх существующего Hermes. Нужен уже имеющийся Python 3.10+. Новые библиотеки не устанавливаются.

В защищённом окружении процесса задайте:

- `HH_ACCESS_TOKEN` — существующий действующий токен работодателя;
- `HH_USER_AGENT` — идентификатор приложения и реальный контактный email;
- `HH_REVIEW_TELEGRAM_TOKEN` — токен отдельного бота согласования;
- `HH_REVIEW_OWNER_ID` — числовой Telegram ID владельца.

Токены нельзя вставлять в чат, GitHub и команды, сохраняемые в историю. Можно использовать `windows/Start_Candidate_Review.ps1`: он запрашивает отсутствующие секреты скрытым вводом, хранит их только в окружении дочернего процесса и восстанавливает исходное окружение после завершения. Он не читает `.env`, не создаёт автозапуск, не меняет существующие профили и не добавляет бота к посторонним чатам.

Запустите тесты из корня репозитория:

```text
python -m unittest discover -s hh-recruiter/tests -v
```

Проверка подключения без отправки сообщений:

```text
python hh-recruiter/scripts/candidate_questions.py check
```

Откройте личный чат с новым ботом и нажмите Start. После успешной проверки:

```text
python hh-recruiter/scripts/candidate_questions.py run --vacancy 137056588
```

По умолчанию рассматриваются сообщения с момента первого запуска. Начало периода сохраняется в базе. Если нужна история, при ПЕРВОМ запуске задайте `--since 2026-09-28T00:00:00+03:00`. Для другого периода используйте отдельную базу `--db`; не редактируйте старую.

Команды боту: `/status` — счётчики, `/pending` — повторно показать ожидающие карточки. Повторное отображение отменяет прежние кнопки. Для изменения нажмите кнопку и ответьте на сообщение-приглашение новым текстом, затем подтвердите новую карточку.

Локальные команды:

```text
python hh-recruiter/scripts/candidate_questions.py status
python hh-recruiter/scripts/candidate_questions.py draft --question 1 --text-file answer.txt
```

`draft` не отправляет ответ. Обработчик подхватит новую версию на следующем проходе. База находится в `hh-recruiter/workspace/questions.sqlite3` и исключена из Git. Папка содержит переписку: ограничьте её доступ текущей учётной записью Windows.

Если получен `unknown`, `blocked` или зависшее решение, откройте HH и сверьте историю. Программа не предоставляет кнопку слепого повтора. После проверки ответ можно отправить вручную. Не удаляйте базу для повторного запуска: это уничтожит защиту от повторной обработки.

## Проверка перед постоянной работой

На тестовой переписке отдельно проверить владельца, отказ, редактирование, повторное нажатие, ошибки сети, перезапуск и фактическую доставку в HH. Приёмка на ПК и решение о службе/автозапуске выполняются после этого. Этот выпуск не закрывает задачи Google Workspace, Metricool, каталога 200 агентов и настройки Windows.
